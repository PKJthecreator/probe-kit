# probe-data-check — 데이터 첫 점검

지침 파일(`~/probe-kit/AGENTS.md`, 킷을 다른 곳에 뒀으면 그 경로)을 새 세션이거나 대화가 압축됐거나 지침이 불확실하면 먼저 다시 읽는다.

## 0. 환경
probe-frame 1의 환경 점검을 아직 안 했으면 먼저 한다: `git --version; date '+%F %T %Z %z'; python3 -V; node -v; npm -v` (데이터 과제면 `python3 -c "import pandas, sklearn; print('pkgs ok')"`도)
대체 경로와 시간대 보정은 probe-frame 1을 따른다.

## 과제 유형별로 쓸 부분 (BRIEF의 유형)
- 예측: 1~4 전부.
- 집계·분석: 1(타깃 줄 제외), 2의 행·키·단위, 3, 4.
- 구현: 1의 입력 형식·키·결측, 2의 단위·코드값. 정상·경계·실패 입력 후보를 뽑아 둔다.

## 1. 프로파일
스크립트 하나로 점검한다(`check_data.py`, pandas가 없으면 `csv` 모듈, 파이썬이 없으면 과제 언어로). 원본은 읽기만 한다. 출력은 30줄 이내 요약.
- shape, dtypes, 열 요약. 원본 행은 기본으로 출력하지 않는다(이름·사번은 정규식으로 다 못 가린다). 민감정보가 없다고 확인한 뒤에만 `--show-rows`로 가린 앞 3행
- 파일 첫 줄·주석·자유 텍스트 열·예시 문서에 비밀값(접속 문자열·비밀번호·키)과 개인정보(이름·사번·전화번호)가 있는지 위치만 적는다. 값 자체는 대화·문서·테스트 데이터·커밋에 옮기지 않는다(테스트에는 가짜 값)
- 파일 형식 함정: 헤더 앞 메타 줄과 헤더 뒤 손상 줄(`#`으로 시작해도 주석으로 삼키지 않음), 엑셀로 열었다 저장한 파일(BOM, `H:mm` 시각, 끝자리 0 생략), 같은 기간을 다시 받은 파일, 파일 경계에서 겹치는 줄, 파일마다 다른 열 이름·단위·시간대(`Z`=UTC), 여러 판의 기준 문서
- 결측 비율(0이 아닌 컬럼만), 완전 중복 행 수, 특징은 같은데 타깃이 다른 행 수(예측), 값이 하나뿐인 컬럼
- 키 후보 컬럼: 고유값 수 대 행 수
- 시간 컬럼: 범위, 정렬 여부, 간격, 빈 구간, 기준일과의 관계, 시간대 표기(Z·+09:00·없음)가 섞였는지(표기 없는 시각을 임의로 KST·UTC로 해석하지 않는다). 기간을 앞뒤로 나눠 타깃 비율·주요 컬럼 평균·결측률이 달라지는지 본다(크게 다르면 그 시점의 공정·정책 변경을 담당자 질문 후보로)
- 타깃(예측 과제): 분포와 불균형 비율. 라벨 있는 학습 데이터에서만 본다. 라벨 있는 test가 따로 주어졌으면 그 타깃은 보지 않는다
- 라벨 없는 제출용 test가 있으면 같이 본다: 컬럼이 학습 데이터와 같은가, ID 중복·결측, 학습에 없던 범주
- 수치 컬럼: min / 중앙값 / max. "이 값이 실제로 나올 수 있나?"를 본다(음수, 0, 물리적으로 불가능한 값). 치우친 분포는 평균 대신 중앙값과 IQR로 요약한다.

## 2. 데이터 계약 — BRIEF의 "데이터" 항목에 짧게
- 한 행 = 무엇, 키 = 무엇. 변수 종류(범주·순서·연속)와 그에 맞는 비교 방법
- 타깃 정의와 그 값이 정해지는 시점. 기준일이 있으면 입력은 기준일 이전 구간, 타깃은 이후 구간만 쓴다
- 누수: 예측 시점에 알 수 없는 값은 입력에서 뺀다. 타깃과 거의 1:1이거나 그 열 하나로 점수가 비정상적으로 높은 열, 이름에 판정·결과·hold·flag·label이 든 열은 누수 후보로 표시하고 담당자에게 "이 값은 언제 기록되나요?"로 확인한다
- 식별자(설비·로트·고객 ID 등)는 지우지 않는다. 문자열 ID를 숫자로 자동 변환하지 않는다(앞자리 0·큰 정수가 읽기·조인·출력에서 깨지지 않았는지 원본 몇 행과 대조). 조인, 그룹 분할, 제출 순서 복원에 필요하다. 모델 입력으로 쓸지는 따로 판단하고 근거를 결정 절에 남긴다(대부분은 입력에서 제외)
- 분할은 실제 사용 장면에 맞춘다. 과제가 분할·검증 방식을 정했으면 그대로 따른다.
  - 이미 있는 설비·고객의 미래를 예측 → 시간 순서 분할
  - 처음 보는 설비·로트·고객으로 일반화 → 그룹 분할(같은 그룹이 학습과 검증에 섞이지 않게)
  - 시간·그룹 구조가 없음 → 무작위 분할(분류면 층화)
  - 완전 중복 행이 학습과 검증에 걸치면 점수가 부풀려진다. 분할 전에 처리 방식을 정한다
- "테스트"를 둘로 나눠 부른다. 분할 기준(시점·그룹·seed)은 고정해 결정 절에 적는다.
  - 내부 holdout: 라벨이 있는 평가용 데이터(내가 떼어 둔 것, 또는 과제가 라벨과 함께 준 test). 최종 확정 뒤 한 번만 평가한다
  - 제출용 test: 과제가 준 라벨 없는 파일. 첫 완주부터 추론해 제출 형식을 확인한다
- 평균·스케일·인코딩 같은 전처리 통계는 학습 분할로만 계산한다
- 단위·코드값·결측의 의미(측정 안 함인지 0인지)가 불확실한 컬럼은 업무 담당자 질문 후보로 넘긴다
- 자료만으로 의미·처리 기준을 정할 수 없고 답에 따라 처리가 달라지는 함정은 처리하기 전에 담당자 확인 질문으로 바꿔 대화에 남긴다(개인정보·비밀값은 쓰지 않는다). 담당자에게: "두 장비 값 단위가 같나요?" / "두 자료에 같은 항목이 다르게 적혀 있는데 현장에선 어느 쪽을 기준으로 보세요?"(기준 자료) / "같은 건으로 보이는 기록이 여러 줄인데 어떤 경우를 한 건으로 보세요?"(중복·집계 단위) / "이 칸이 비어 있으면 무슨 뜻이고 그땐 어떻게 하세요?"(결측) / "취소·시험용 기록도 섞여 있나요?"(제외 대상)
- 경계 판단표를 BRIEF(과제 문서면 PRD)에 둔다: `주제 | 규칙(포함/제외) | 근거(담당자 답) | 데이터 속 사례`
- 특수코드(-9999 등)를 결측으로 바꾸거나 값을 대체하면 `열_isna` 같은 플래그를 남겨 실측과 구분한다(`templates/data-ml/features.py`의 `mark_missing`)
- 센서 로그처럼 한 행이 한 시점이면, 예측 단위(웨이퍼·로트·런)로 먼저 집계한 뒤 그 단위로 분할한다(`aggregate_runs`). 같은 단위가 학습·검증에 걸치지 않게

## 3. 집계 함정 — 분석·보고형 과제에서 특히
- 분모가 무엇인가(전체인가, 해당 그룹인가). 비교 기간이 같은가
- 전체 비율과 그룹 비율의 단순 평균은 다르다. 가중 여부를 밝힌다
- 취소·반품·테스트·중복 건을 뺐는가. 고유 개수와 건수를 구분했는가
- 퍼센트와 퍼센트포인트, 그래프 축 범위
- 조인 전후 행 수를 출력한다. 늘었으면 키 중복부터 확인한다
- 반도체·제조 데이터면 분자와 분모를 같은 모집단으로 맞춘다(결함 건수와 불량 개체 수는 다르다). die·wafer·lot·package 단위와 최초·최종 검사를 섞지 않는다. 재검사 기록은 지우지도 더하지도 말고 어느 판정을 셀지 정한다(모르면 담당자 질문). 조인 전후 개체 수와 분자·분모가 보존되는지 본다. 관리한계 이탈은 조사할 신호이지 규격 불합격이나 원인 확정이 아니다

## 4. 이상값과 그룹
- 지우기 전에 기록 오류인지 실제 공정 특성인지 구분한다. 근거가 없으면 유지하고 `[미확인]`으로 남긴다.
- 전체 경향과 그룹별(설비·공정·제품·기간) 경향을 나눠 본다. 방향이 뒤집히면(심슨의 역설) 보고한다.
- 데이터가 특정 기간·설비에만 몰려 있지 않은지, 즉 결론을 넓혀도 되는 표본인지 본다.
