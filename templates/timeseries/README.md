# timeseries — 수요·생산량·계측값의 미래 예측

쓰는 때: 월별 수요, 일별 생산량, 설비 센서의 다음 값, 재고 소요 예측.
첫 명령: `python forecast.py --data sales.csv --id item --time month --y qty --h 1 --season 12` (자체 점검 `--demo`)
필요: pandas, scikit-learn. 입력은 롱 포맷(대상ID·기간·값) 한 장, 빈 기간은 미리 채운다.

하는 일: 수요 유형 분류(ADI·CV²) → 기준선(직전값·계절 직전값·3기 이동평균) + 전역 부스팅(시차는 h 이상만) → 기준 시점을 한 기씩 옮기는 롤링 백테스트 → WAPE·편향(유형별로도) → 후보가 최선 기준선보다 `--margin` 이상 좋을 때만 채택 → 다음 h기 예측.

## 기술 후보
| 층 | 후보 | 언제 |
|---|---|---|
| 기준선 | **계절 직전값·직전값·이동평균**, ETS(statsmodels) | 항상. 이걸 못 이기면 기준선을 발행한다 |
| 주력 | **전역 부스팅(시차·이동통계·달력·대상 코드)**, LightGBM(설치 시) | 대상이 많을 때 한 모델로 |
| 간헐 수요 | Croston SBA·TSB(statsforecast 설치 시, 아니면 0 비율×평균 크기) | 0이 많은 품목 |
| 통계 모형 | ARIMA·ETS(statsmodels) | 대상이 적고 계열이 길 때 |
| 구간 | 백테스트 잔차 분위수(콘포멀), 분위수 회귀 | 재고·안전재고 판단에 범위가 필요할 때 |
| 계층 정합 | 상향식 합계(BottomUp), MinT(hierarchicalforecast) | 품목·고객·공장 합계를 맞춰야 할 때 |
| 딥러닝 | LSTM(PyTorch·Keras) | 이력이 길고 대상이 많으며 시간·실행 환경이 될 때만. 같은 롤링 백테스트에서 기준선을 이겨야 채택 |
| 시각화 | 실측 vs 예측 선 그래프(matplotlib → PNG) | 큰 오차 구간·편향을 보여 줄 때 |

## 현업 수준 체크
1. 무작위 분할 없이 시간순 백테스트만 썼다. 모델·신호를 고른 구간과 마지막 평가 구간을 나눴다
2. 입력에는 예측 발행 시점에 공표된 값만 썼다(as-of). 외생변수는 그 시점에 알 수 있던 값만
3. 기준선과 같은 구간에서 비교했고, 못 이긴 대상은 기준선을 그대로 냈다
4. 지표: WAPE(합계 0이면 계산 불가 표시), 편향 방향, 유형별 결과를 함께 보고했다
5. 예측 변화가 크면 원인을 "확인된 사실 / 원인 후보"로 나눠 설명했다(상관을 인과로 쓰지 않음)
6. 경보는 진입은 즉시, 해제는 연속 조건(비대칭 히스테리시스). 추적 신호 |TS|>4는 `../data-ml/spc.py`
